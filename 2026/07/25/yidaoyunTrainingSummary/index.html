一、基础部分 — cppbase

项目简介

cppbase 是 C++20 基础组件从零实现与性能基准测试项目。核心理念是不依赖标准库，从零造轮子，深入理解底层机制。每个模块配套 Google Test 功能测试 + Google Benchmark 性能基准，形成与标准库的量化对比。

技术栈：C++20 · CMake · Google Test · Google Benchmark · Python Matplotlib

模块一：hstring — 自定义字符串

完整实现 my::string，核心设计包括：

  • SSO（小字符串优化）：15 字符以内栈上存储，避免堆分配
  • copy-and-swap：强异常安全保证
  • KMP 子串查找：O(n+m) 时间复杂度
  • 全套 API：构造/拷贝/移动、append/insert/erase、split、compare、迭代器

性能：大部分操作达到 std::string 的 5~15 倍，尤其是构造（快 15x）、拷贝（快 14x）、移动赋值（快 9x）。find/compare 略逊于标准库，差距在 20-30%，这是因为编译器对标准库有深度优化。

模块二：my::unique_ptr — 自定义智能指针

仿 std::unique_ptr 的完整实现，核心设计：

  • compressed_pair + EBO：空删除器零额外开销
  • 数组偏特化：unique_ptr<T[]> 提供 operator[]
  • SFINAE + C++20 Concepts：编译期约束模板参数
  • 33 项 GTest 测试全部通过：单对象 19 项 + 数组 14 项

性能：make_unique 快 39%、reset 快 12%、release 快 9%，整体接近甚至超越标准库。

模块三：IO 多路复用对比

实现了 select / poll / epoll 三套回声服务器，统一非阻塞 I/O 设计确保公平对比。配合 redis-benchmark 进行 10~5000 并发的系统压测：

  • epoll 纯性能最优，1000 并发达到 84,818 RPS
  • select 在低并发 (<2000) 表现意外亮眼，但高并发直接超时
  • reactor-epoll 高并发最稳定，5000 并发仍有 70,373 RPS

二、系统与框架

reactor_module — Reactor 高并发网络框架

基于 Reactor 设计模式，在 Linux 环境实现了高并发、可扩展的网络服务器框架。这是 cppbase 中 epoll 实现的架构升级版本——从单文件过程式代码演进为 8 个类的面向对象架构。

核心架构：Main-Reactor（accept）+ 2× Slave-Reactor（I/O 处理）+ ThreadPool(4)（业务计算）

关键技术：

  • epoll 边缘触发（ET） + 非阻塞 I/O：减少事件通知次数
  • eventfd 跨线程唤醒：主 Reactor 向从 Reactor 安全投递任务
  • timerfd + 最小堆优先队列：内核定时器与 epoll 完美融合
  • 工厂模式注入 Handler：业务与框架解耦，支持 Echo / Redis PING 协议切换
  • 线程安全：每个 Reactor 独立状态，零锁竞争；跨线程通过 eventfd + 任务队列通信

压测结论：reactor-epoll 在高并发（2000~5000）场景是唯一稳定通过的模型，体现了架构设计对可扩展性的价值。

TetrisGame — Qt 6.8 / QML 俄罗斯方块

经典俄罗斯方块，采用 C++ + QML 混合架构：C++ 负责全部游戏逻辑状态，QML 负责纯渲染。

核心技术：

  • C++ ↔ QML 桥接：qmlRegisterSingletonInstance 注册 C++ 单例到 QML
  • 400 个原生 QML Rectangle 替代 Canvas 渲染，利用 GPU 合成
  • 程序化 PCM 音频合成（方波+正弦），无外部音频文件，QAudioSink 播放
  • Qt 6.8 qmlcachegen 踩坑：Canvas onPaint 不触发→换 Rectangle；嵌套 QVariantList 访问失败→换逐格 int 访问器；绑定不追踪 Q_INVOKABLE 依赖→引入 stateRevision 计数器强制重算
  • 最终架构原则：全部逻辑下沉 C++，QML 零游戏逻辑、零条件判断

收获：深入理解了 Qt 框架的限制与边界，学会了在编译器和框架的约束下做出务实的设计决策，而非死磕"正确"方案。

三、企业实战

coronet — C++20 协程 · 跨平台高性能异步 I/O 库 ⭐

coronet 是本培训的核心成果项目，一个生产级 C++20 协程异步 I/O 库，自主实现协程运行时，支持 Linux epoll / io_uring / Windows IOCP 三后端，并提供 TLS 加密传输。

核心特性

特性 说明
三后端热插拔 epoll ⇄ io_uring（-DCORONET_IOURING=ON）⇄ IOCP（Windows 自动），编译期切换
全编译器跨平台 Linux GCC 13 / Clang 18 + Windows MSVC 19.41，一套代码
TLS 加密 OpenSSL 3.x，双向验证 + ALPN，内存 BIO 桥接同步 SSL 到异步事件循环
编译期零开销多态 CRTP + #ifdef 平台选择，无虚表、无堆分配 Proactor
链式 co_await co_await (send && recv) 单次挂起完成两个 I/O 操作
协程同步原语 mutex / condition_variable / semaphore / channel / when_all·any·some

性能数据

  • C1000K 压测通过：1,000,000 请求 × 1,000 并发，单线程 50,955 RPS，6 线程 50,140 RPS
  • vs ASIO 对比：6 线程 比 ASIO 快 67%，CPU 低 61%
  • 三平台峰值：Windows MSVC IOCP 58,384 RPS（单线程最高）
  • 27/27 测试全平台通过（GCC/Clang/MSVC + epoll/io_uring/IOCP）

架构亮点

关键技术决策：

  • 惰性协程 task<T>：父链内联恢复，零调度开销
  • SPSC 无锁环：跨线程任务投递，避免锁竞争
  • shared_task<T>：引用计数多等待者，支持协程组合器
  • io_context：栈上 Proactor，无堆分配

coronet 证明了从零实现高性能协程运行时完全可行，且在核心指标上可比肩甚至超越业界标杆 ASIO。

RemoteCtrl — 远程控制软件

基于 coronet 协程库的实用远程控制软件，包含客户端和服务端。

功能：

  • 文件管理：远程浏览目录树、文件下载（断点续传）、删除、远程打开
  • 桌面监控：实时屏幕共享 ~20 FPS，GDI BitBlt + WIC JPEG 硬件编码，鼠标事件转发
  • 终端控制：远程锁屏/解锁
  • 守护进程：开机自启、后台静默运行

架构：

  • 服务端：coronet 单线程协程，acceptLoop + SessionHandler + screenStream
  • 客户端：Qt5 Widgets + coronet 独立 I/O 线程，mutex 队列桥接
  • 协议：自定义二进制协议，magic + 命令 + 载荷 + CRC32C（SSE4.2 硬件加速）
  • 编码：全链路 UTF-8，中文文件名零乱码

技术价值：将 coronet 应用到真实产品场景，验证了异步协程在 GUI 应用中的可行性——Qt 主线程不阻塞，I/O 在协程线程异步处理。
